# ホームダッシュボード案

## 目的

毎日確認したい生活・活動・自宅サーバーの情報と、サービスへの入口を1画面に集める。ホームでは要点を確認し、履歴の確認や記録の入力は詳細画面で行う。

現在はホームに天気カードと既存の騰落率の表を表示している。以下は今後の配置案で、株価の詳細画面への分離や他のカードは未実装。

## 表示したい情報

| カード   | ホームに表示する内容                            | 詳細・移動先                 |
|----------|-------------------------------------------------|------------------------------|
| 天気     | 東京都の5日予報（天気・最高／最低気温・平均湿度） | 当初はカード内で表示         |
| サーバー | ラズパイ本体のCPU・メモリ・温度・ディスク使用率 | 使用率の推移                 |
| サービス | 稼働状態・応答確認・サービスへのリンク          | 各サービス・稼働履歴         |
| GitHub   | 今日のコミット数・直近の活動                    | 日別の活動履歴               |
| 筋トレ   | 今日のメニュー、または直近の記録                | 種目・重量・回数の記録と入力 |
| 株       | 最新取引日の上昇率上位3件程度・対象日           | 既存の騰落率上位10件の表     |

## 配置案

```text
ヘッダー：ホーム名・詳細画面への移動

天気              サーバー          サービス
GitHub            筋トレ            株
```

PCではカードを並べ、スマートフォンでは縦に配置する。最初は固定配置とし、余白を持たせる。カードの自由配置やテーマ編集は後から検討する。

## データと状態の扱い

天気の取得元とキャッシュの設計は[weather-design.md](weather-design.md)を参照する。

- 現在のSvelte・Go API・MySQLの構成を継続する。
- 外部サービスの認証情報はGo側で管理する。
- 更新頻度は情報ごとに決める。サーバーは短い間隔、天気・GitHubは数十分以上、筋トレは記録時などを目安とする。
- カードごとに対象日時・最終取得日時を表示し、古い情報だと分かるようにする。
- 読み込み中・取得失敗・データなし・活動0件を区別する。1つのカードの失敗で他のカードを表示できなくしない。

## 最初に作る範囲

天気カードと既存の騰落率の表を同じ画面に表示するところまで実装済み。株価の詳細画面への分離や他のカードは順に追加する。天気は東京都庁を代表地点とする。座標と選定理由は[weather-design.md](weather-design.md)を参照する。GitHubの集計範囲、筋トレの記録方法、監視情報の取得方法は各機能の実装前に決める。
